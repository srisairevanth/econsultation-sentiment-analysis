## MODULE 3 — TF-IDF + Classical ML Sentiment Pipeline

**Location:** `mini projjjj/` (this folder). **Files found:** `preprocessing/{text_utils.py, clean_dataset.py}`,
`training/{model_utils.py, train_model.py, compare_models.py, evaluate_model.py}`,
`prediction/{predictor.py, batch_predict.py}`, `analytics/{analytics.py, visualizations.py}`,
`models/{best_sentiment_model.joblib, model_metadata.json}`, `reports/*`, `scripts/make_sample_dataset.py`,
`app.py`, `chatbot/*`.

### Dataset verification (`preprocessing/clean_dataset.py`)
All required checks are implemented and produce a real report (`reports/dataset_quality_report.json`):
required columns detected via alias matching, labels validated against the exact 3-class set (1 invalid
`"Mixed"` label was found and removed in the last run), null/empty comments removed (4 removed), exact
duplicates detected and removed (127 removed), length statistics computed, class distribution and
imbalance ratio computed (1.36, below the 3.0 flag threshold). ✅ Matches your checklist exactly.

### Preprocessing (`preprocessing/text_utils.py`)
Conservative, as required: Unicode NFKC normalization, control-character stripping, whitespace
collapsing/trimming. Explicitly does **not** lowercase, strip punctuation, remove stopwords, or touch
negation words (`not/no/never/cannot`) — confirmed by reading the code, which states this reasoning in
its own docstring. No aggressive NLP preprocessing, no silent data loss (everything removed is counted
in the quality report). ✅

### Feature extraction
`TfidfVectorizer(ngram_range=(1,2), min_df=2, max_df=0.95, sublinear_tf=True, max_features=20000)` —
unigrams + bigrams as required. **No data leakage**: verified in `train_model.py` — the vectorizer lives
inside each model's `sklearn.Pipeline`, `GridSearchCV` cross-validates only on `train_df`, the 3-model
comparison fits only on `train_df` and evaluates on `val_df`, and the winning model is refit on
`train+val` with a single final `.predict()` on `test_df` — the test set is never seen before that one
call. ✅

### Models compared
Logistic Regression, Linear SVM (`LinearSVC` + `CalibratedClassifierCV` for confidence scores, since
`LinearSVC` has no `predict_proba`), and Multinomial Naive Bayes — all three, on the identical TF-IDF
configuration and the identical train/val split. A GridSearchCV-tuned LogReg variant is also included as
a fourth candidate. ✅

### Data splitting
Stratified 70/15/15, `random_state=42`, with an automatic 80/20 + cross-validation fallback for small
datasets (`< 150 rows` or a minority class `< 10`) — not triggered on the current dataset (174 rows, just
above the threshold). Test set is written to `test_split.csv` once and only read for the single final
evaluation. ✅

### Evaluation
Accuracy, per-class precision/recall/F1, macro F1, weighted F1, and confusion matrix are all computed
(`evaluate_predictions()`), and Macro F1 is the primary selection key
(`rank_key = (f1_macro, f1_weighted, accuracy)`). ✅

### Model saving
`models/best_sentiment_model.joblib` exists (51.6 KB). `models/model_metadata.json` exists and contains
model type, selection reason, training date, random seed, dataset size, class distribution, split info,
tuned hyperparameters, full test-set metrics, and the full candidate comparison table. ✅ Matches your
checklist exactly.

### Prediction
`prediction/predictor.py` and `prediction/batch_predict.py` both call `joblib.load()` on the saved model
only — **neither file imports or references Ollama, Qwen3, Gemini, or any LLM API.** Confirmed: future
prediction genuinely does not require the LLM. ✅

### 🔴 THE CRITICAL CAVEAT — read this before your panel

**Every number currently in `model_metadata.json`, `reports/dataset_quality_report.json`, and
`reports/*evaluation*.json` comes from a 100%-synthetic, template-generated dataset**
(`scripts/make_sample_dataset.py`), **not from real Regulations.gov comments or real Qwen3 labels.**

I read that script directly. It generates sentences from 8 hand-written templates per class, filled in
with combinations of 8 "groups" and 8 "topics" (e.g. *"This regulation will create unnecessary compliance
costs for {small banks}."*). This is exactly why:
- 127 of 306 generated rows were exact duplicates (limited template × group × topic combinations repeat)
- the final model hits **100% accuracy and 100% macro-F1 on the test set** — template sentences with
  fixed vocabulary per class are trivially separable; this is not a realistic result for messy real-world
  public comments.

The script itself says so in its own docstring: *"This is NOT real regulatory data and must not be
presented as such."* I'm repeating that instruction here because it's the single most important finding
in this report:

> **Synthetic pipeline verification results — NOT real project performance.**
> Total dataset: 174 rows (synthetic) → Test accuracy 1.0, Macro F1 1.0, model selected: `tfidf_linear_svm`.
> This proves the *pipeline* works end-to-end. It proves nothing about how the model will perform on real
> public comments, because no real comments have been run through it yet (Modules 1 and 2 have not
> produced real data — see above).
